# Master Roadmap — LHL App

This file is the sole canonical task tracker for LHL. It is maintained in Git so John, Claude, and Codex share one reviewable record. The former Google Sheet is retired as a tracker; its source workbook remains outside this repository as a personal backup.

Use the exact task name when reporting progress or blockers. Active and backlog dates are approved targets unless labeled `Not set`, `Not recorded`, or `Not separately scheduled`; dates in the archive are historical completion dates. `docs/05-gate-framework.md` controls sequencing and gate exit criteria, while this roadmap controls task status.

Status reviews must cover three lanes rather than the current product gate alone: (1) work required to close the current gate, (2) every active `Ops` task and any other non-gate milestone due before the next gate closes, and (3) backlog items whose scheduling-review trigger or due date is approaching. Gate focus controls product sequence; it does not make operational, legal, financial, account, or business-infrastructure work optional.

Before marking any task Complete, verify its Target Output and ask John for explicit confirmation. Once confirmed, never delete the row: set Status to `Complete`, replace Due Date with `Historical: YYYY-MM-DD` using the actual completion date, and move the full row to Archive. Do not strikethrough task names; Archive placement is the completion indicator. Routine completion/archive moves do not require a changelog entry; material scope, priority, schedule, or task-structure changes still do.

## Parked Internal Tools

### Market Intelligence Agent v2

- **Status:** Parked; not assigned to a product gate. Revisit after G2 closes, currently targeted for 2026-08-28.
- **Owner:** John retains the approval and scheduling decision.
- **Product boundary:** This is a personal situational-awareness tool for John, not part of ECA and not required for any gate.
- **Origin:** John built v1 independently in Gemini using Tavily search, Gemini 2.5 Flash extraction/scoring, and yagmail email delivery. GEM, Claude, and Cody did not build it. It produced useful signal at least once, including notification/alert-fatigue research that informed MVE-1 thinking. Full session detail remains in John's Claude chat history.
- **Why parked:** It is not gate-blocking and is explicitly deprioritized below G2 closure and the WildWeb permission inquiry.

#### Known v1 problems and likely root causes

1. **Staleness and repetition:** Four broad Tavily queries ran daily without memory of prior output, deduplication, or delta detection. The appropriate fix is a persisted seen-item log, not a larger extraction schema.
2. **Manual execution:** John had to invoke the script manually. Scheduling through cron, launchd, a GitHub Action, or an approved scheduled coding-agent task is an implementation choice rather than a core design problem.
3. **Overcomplicated stack:** Tavily plus Gemini is viable in principle, but the 105-point, three-vector severity rubric and multi-lane HTML email added complexity without clearly demonstrated value. A v2 may be able to use a simpler single-provider search, scoring, and summarization flow, subject to a later tool and cost decision.

#### Security note

The v1 script contained a Tavily key, Gemini key, and Gmail app password in plaintext. John rotated all three credentials as a precaution. The probability that they reached the public repository was assessed as low because the Gemini workflow had no repository write path, but the Git-history-check status remains to be confirmed by John and is not represented here as complete.

#### Restart conditions

- Store secrets in environment variables or an approved secret store, never in source files.
- Persist a deduplication log so previously reported stories do not recur without a material update.
- Reduce scoring to three to five plain criteria.
- Automate execution through a deliberately selected scheduler instead of manual invocation.
- Scope the work as a small, isolated coding task rather than rebuilding the entire prototype.
